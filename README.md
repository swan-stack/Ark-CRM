# ARK LP CRM — 암호화 배포본 (무료 GitHub Pages용)

`index.html` **한 파일**이 전부입니다. 데이터는 **AES-256-GCM 암호문**으로만 들어 있고,
접속 시 **암호(passphrase)** 를 입력해야 브라우저에서 복호화되어 대시보드가 열립니다.
소스를 봐도 암호문뿐이라 암호 없이는 내용을 볼 수 없습니다.

> **현재 임시 암호: `ark-lp-2026!`  → 공유 전에 반드시 강한 암호로 바꾸세요(아래 3항).**

---

## 1. GitHub Pages 배포 (무료)
```bash
cd lp-crm-secure
git init && git add index.html README.md
git commit -m "LP CRM 암호화 배포본"
# GitHub에서 리포 생성 후:
git remote add origin https://github.com/<계정>/lp-crm.git
git branch -M main && git push -u origin main
```
- 리포 → **Settings ▸ Pages ▸ Source: main / (root) ▸ Save**
- 몇 분 뒤 `https://<계정>.github.io/lp-crm/` 로 접속 → 암호 입력 → 사용.
- 리포는 public이어도 됩니다(암호문만 들어있음). 단, **암호문은 공개 노출**되므로
  **오프라인 무차별 대입**을 막으려면 **암호를 반드시 강하게**(4단어 이상 무작위 조합 권장).

## 2. 테스터 공유
- URL은 Teams 공지/메일로, **암호는 별도 경로(Teams DM 등)로 따로** 전달하세요(같이 X).
- 안내문 예시:
  > LP CRM 테스트입니다. 링크 접속 → 암호 입력(별도 전달). 크롬/엣지 권장.
  > 좌측 LP 선택, 상단 탭·검색·정렬, 관리자 모드로 편집/승인 사용해보시고 피드백 주세요.
  > ※ 현재는 각자 화면에만 반영(공유 저장 아님), 링크·암호 외부 유출 금지.

## 3. 암호 바꾸기 (권장 · 강한 암호로 재빌드)
암호는 파일에 저장돼 있지 않고, **재암호화로만** 변경됩니다.
`build_encrypt.js` + 원본(`ARK_LP_CRM_대시보드.html`, `lp_crm_data.json`)이 있는 폴더에서:
```bash
node build_encrypt.js "새로운-강한-암호-여기"
```
→ `lp-crm-secure/index.html` 이 새 암호로 다시 생성됩니다. (Node 설치 필요)
Node가 없으면 저(어시스턴트)에게 "이 암호로 다시 빌드" 라고 하시면 만들어 드립니다.

## 4. 한계 (정직하게)
- **공유 암호 1개** 방식 → 개인별 계정·권한 회수·"누가 봤는지" 감사 불가.
- 암호를 받은 사람은 파일을 저장해두면 이후에도 복호화 가능(회수 불가).
- 정당 접속자의 화면 캡처·데이터 내보내기는 원천적으로 못 막음(클라이언트 앱 특성).
- 암호문이 공개되므로 **약한 암호는 오프라인에서 뚫릴 수 있음** → 강한 암호 필수.
- 편집 내용은 각자 브라우저에만 남고 서로 동기화되지 않음(테스트/피드백용).

이 방식은 **테스트·미리보기용**입니다. 실사용(개인 로그인·권한·감사·실시간 공유)은
**SSO 호스팅** 단계에서 완성됩니다.

## 파일

- (비공개 보관) `build_encrypt.js` · `ARK_LP_CRM_대시보드.html` · `lp_crm_data.json`
